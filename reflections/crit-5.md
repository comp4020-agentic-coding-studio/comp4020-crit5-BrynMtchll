# Reflections

### q1
The breakthrough was making proper use of CLAUDE.md. The file also grew a new rule mid-project: tests that check a curve can be green while the game itself is unplayable. Writing that down turned a one-off lesson into something that would catch the same mistake next time, on a different project. The file stopped being documentation and started being a set of sensors I trusted more than my own memory of what was true.

### q2
I want to build systems that make good work the default, not something I have to remember to do. A probe that reports real pixel coordinates instead of me eyeballing a screenshot. A rota-based test instead of trusting a curve looks right. A rules file that gets corrected the moment it's caught lying, instead of drifting quietly out of date.

The pattern I want to keep is: when I catch a gap, close it with a system, not a mental note. Mental notes decay. A sensor or a written rule doesn't — it just sits there and does the job again next time.
